# 页面检测与安全调节

## 检测时机

HTML 在 `document.fonts.ready` 后测量；内容编辑、照片变化和打印前重新测量。测量只改变 Format Profile 允许的 CSS 变量，不改变正文参数或内容结构。

`preview_resume_html.py` 服务的是启动时复制出的静态文件。源成品在服务启动后发生任何修改，旧 URL 不再是有效 QA 基线；停止旧服务并从最新成品重新启动预览。视觉检查前先确认页面出现本轮修改后独有的文字或字段，并确认被删除的旧文字已经消失，避免对旧副本完成 QA。

## 后台检测

- A4 内容底部与实际内容底部的差值；
- 超出高度折算成 13.5 pt 正文行数；
- 每条 bullet 的真实行框及最后一行有效字符数；
- 大标题或公司或项目标题是否与后续内容分离；
- 左名称、中间字段和日期是否碰撞或横向越界；法律实践与科研成果的中间字段是否共同使用 Profile 锁定的 `research-middle-anchor`，且日期始终贴右边界；
- 全局宋体栈与标题微软雅黑栈的首选字体是否可用；
- 打印前是否仍使用 A4 尺寸。
- 四个大标题的粗下划线与右侧横线是否无缝衔接并共享底部基线；
- 教育、法律实践和科研成果的日期是否统一贴各自内容区右边界；
- 页眉照片、姓名和联系方式是否越界或互相挤压。

HTML 通过 `window.resumeQa()` 暴露机器可读结果。短尾结果必须能定位到具体 DOM 节点、所属经历、尾行文字和等价字符数；它只是候选提示，模板和浏览器不得据此修改正文。

正常时不显示诊断面板；有影响交付的未解决错误时只显示最重要的一句。单独出现的短尾只是内部候选项，不是页面错误；在未超页、未碰撞且视觉可接受时，保留机器数据但不在最终 HTML 中显示“请人工判断”。对已能自主解决的内部 QA 事项，不把判断转交给用户。

## 垂直适配顺序

从 Profile 的默认档开始，按固定候选档位尝试，禁止连续任意缩放：

1. 公司与项目标题行整体调整；法律实践所有公司相同，科研成果所有项目相同。
2. 若仍接近边界，再统一调整四个大标题。
3. 正文、bullet、页边距和横向坐标不动。

轻微超页时选择能够减少溢出的最宽松档位；底部仅有 0–1 行自然空白时，可以选择不导致溢出的最松档位。真实定向内容较少时也必须先运行这一步。明显超过 1–2 行空白时保持默认，不用间距填满；安全档位已经用尽且需要恢复、调入或扩展内容时，Owner 为 Tailor。

底部空白必须以“可打印内容边界减去实际内容底部”计算；已从内容边界中扣除的固定下页边距是打印安全区，不属于可恢复内容的页面留白。不得用纸张物理底边与最后一行的直接距离判断内容是否过少。

## 短尾候选与内容回退

仅在 bullet 最后一行忽略标点后不超过约 5 个中文字符等价宽度，且减少一行确实改善页面时处理。

允许：删除无信息量连接词、重复修饰，或替换为完全等义的更短专业表达。

必须逐项保持：核心事实、对象、数字、日期、个人责任程度、法律判断、交付物和结果。改写后重新运行页面检测；不能减少一行或无法确认完全等义时撤销改写。

机器只定位短尾和可疑节点，不自动落地微压缩。普通正文返回 Writing，`self_summary` 返回本 Skill 的一行自我评价阶段；上游形成新的完整文字版本、更新 content version 与 Change Set，用户完整确认后再渲染。纯 CSS、spacing、字体或位置调整不触碰内容模型。

局部 HTML 续改完成后，必须运行 `scripts/validate_html_scope.py` 对比修改前后文件，显式列出允许改变的 `data-node-id`，并传入当前 `global_content_constraints` 快照（无记录时为空数组）。非目标内容、结构、日期、数字或正文加粗发生漂移，或允许节点内复活全局禁用文本/节点，均失败；范围外的文字错误只提示。

满足保护条件时，Make 只可自主处理纯 CSS、spacing、字体加载或位置调整并重新 QA；不得自主修改正文、标签或标点。存在完全等义的低风险文字候选时仍返回对应内容 Owner，形成新版本并重新取得完整确认。找不到安全改法时保留正文；若未导致超页或明显孤词，不把“存在短尾候选”本身视为交付失败。最后一行明显超过约 5 个字时，不继续按排版尾巴处理：只需在既定 WHAT 内修正标签、语序、措辞或语言冗余时，Owner 为 Writing；需要改变 evidence、center proposition、bullet 数量、entry、content budget、结构或排序时，Owner 为 Tailor。内容值得完整保留时允许暂时超出约 1–3 行。

## 人工视觉验收

机器结果不能替代真实页面检查。字体加载完成后逐项查看：

- 标题下划线与右侧横线连续、同基线，不穿过字面；
- 教育、法律实践、科研成果的日期使用一致的最右基准；
- 左名称、中间字段和日期没有机械检测未捕捉的视觉拥挤，且法律实践与科研成果的中间字段处于同一垂直轴线上；若只需在既定字段含义内做等义措辞压缩，Owner 为 Writing；若需要改变字段、结构或内容预算，Owner 为 Tailor；
- 没有孤词、异常短尾、标题孤立或不自然换行；
- 照片位置、姓名和联系方式保持已确认模板状态；
- 页面底部实际余量和整体密度自然，没有以拉大间距填空或压缩正文塞页。

如果机器提示与可见页面明显矛盾，先在 Make 内检查字体、内容边界计算、字段定位和预览环境；不得把单一高度数字直接转成用户取舍题。只有确认问题来自正文后，才按下文唯一 Owner 规则返回。

## 上游退回条件与唯一 Owner

Make 先在固定边界内处理 HTML / CSS、A4、真实页面测量、标题孤立、横向碰撞和安全 spacing。仍不能解决时，只报告具体 DOM 节点、测量结果、失败原因和一个 Owner：

- 普通正文需要纯 HOW 调整，且不改变 WHAT、事实或责任边界：Owner 为 Writing；
- 需要删除、恢复、展开、调入、调出或重排 entry，改变 bullet 数量、结构、content budget、center proposition 或 selected evidence：Owner 为 Tailor；
- `self_summary` 一行无法容纳且必须改变文字：Owner 为本 Skill 的一行自我评价阶段。

安全档位后仍明显超页或空白时，Make 只提供真实测量；若解决问题需要改变内容取舍，Owner 为 Tailor。横向异常不得通过擅自缩写正式名称或删减关键信息解决；能够在既定含义内等义压缩时 Owner 为 Writing，需要改变字段或结构时 Owner 为 Tailor。Make 不指定上游使用哪一种具体内容修复动作。

QA 通过必须同时满足：机器无未处理异常、人工视觉清单通过、打印前仍为 A4。文件仅生成、仅保存或仅机器通过都不能称为最终完成。
